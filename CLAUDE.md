# SanoVids — demo

Node-canvas app for producing AI films scene by scene (replacement concept for canvasapp.io.vn).
Frontend (web + Electron desktop). New takes run in **development mode** by default: the real canvasapp gateway code against an in-app **simulated canvasapp.io.vn** (`src/providers/dev/` — no network, fake "credit dev"); the real canvasapp.io.vn gateway is opt-in in the desktop app. The old mock demo only runs takes saved before.

## Run
- `npm run dev` → http://localhost:5180 (or double-click `start.bat`)
- `npm run typecheck`, `npm test` (vitest), `npm run build`
- `npm run dist:win` (signed installers into `release/` through `scripts/electron-build.mjs`; needs the author's signing key in `Cert:\CurrentUser\My` and network for timestamps; scratch/test builds: `npx electron-builder … --publish never -c.directories.output=<dir>` with `ELECTRON_BUILDER_DISABLE_BUILD_CACHE=true`, never into `release/`), `npm run release:check` / `npm run release:publish` (owner only, docs/UPDATES.md), `npm run icons` (all icon files from `build/icon-source/*.svg`)

## Stack
Vite 8 + React 19 + TypeScript 7 (`tsc` is the native compiler) + `@xyflow/react` 12 (React Flow) + zustand 5 + zundo (undo/redo) + lucide-react 1.x + idb-keyval + jszip. Desktop: Electron + electron-builder + electron-updater (desktop main process; the ONLY runtime dependency — renderer libs are devDependencies because Vite bundles them).

## Architecture (read before editing) — schema v2, see docs/SPEC-v2.md
- `src/core/types.ts` — domain model. `Scene.refs` (ordered asset ids) = reference images → `@image_N`; `Scene.videoRefs` (ordered take ids) = reference videos → `@video_N`. Canvas wires are only a view of these lists. No prompt blocks, no auto references paragraph, no scene→scene continuity link.
- `src/core/compile.ts` — pure: the prompt is sent as written; token helpers (`parseTokens`, `imageSlots`, `tokenForAsset`, `remapTokens`), validation warnings/notes. Character sync rules: a token with no media in the request (`unsentTokens`: past the model cap, mode without refs, or an `@image_?N` placeholder) blocks the run; `remapTokens` keeps typed-ahead numbers only on a pure append of new assets, otherwise turns them into `@image_?N`. The queue sends `take.imageKeysSnapshot` (captured with `promptSnapshot`), never the live refs — see `src/__tests__/characterSync.test.ts`. `src/core/staleTokens.ts`: warnings when renumbering is off. `src/core/migrate.ts` upgrades v1 data. Tests in `src/core/__tests__`, `src/store/__tests__`.
- `src/core/models.ts` — model capabilities (image/video limits), credit pricing, `costOf`, `normalizeSettings`.
- `src/store/project.ts` — undoable project store (zundo). Every refs/videoRefs change renumbers prompt tokens in the same undo step. `LAYOUT`, `ROW_H`, `defaultTakePosition`: one scene per row, its takes to the right.
- `src/store/runs.ts` — takes (= video nodes on the canvas, `take.position`) + the job queue engine (not undoable). `removeTakes` also drops them from every scene's videoRefs.
- `src/providers/` — `index.ts`: registry, `activeProviderId()` ('dev' | 'canvasapp', never 'mock'), `activeGateway()` (api + bridge of the dev or real gateway — balance, login, top-up, history all go through it), `resetDevMode()`. `canvasapp/`: the real gateway (api, adapter, mapping, transport). `dev/`: development mode — `server.ts` (simulated canvasapp, faults, persistence), `bridge.ts` (simulated electron gateway), `prompts.ts` (login / SePay sheets), `log.ts` (request log), `validate.ts` + `routes.ts` (strict rules shared with tests / main.cjs allowlist). See docs/SPEC-v2.md §11.
- `src/store/ui.ts` — selection (scene, asset and take ids), view, dialogs, drag overlay, toasts, `takeDisplay`.
- `src/store/persist.ts` — IndexedDB autosave (+ localStorage emergency backup), project list, export/import `.sanovids.json`. All functions are async. Media blobs: `src/lib/imageStore.ts`.
- `src/actions.ts` — shared commands (linkAssets, linkTakes, ensureAssetToken, createSceneFromTake, deleteSelection, run, copy, zip). UI calls these. Use `undoToastAction()` from the project store for toast undo buttons.
- Edge ids: `ref:<assetId>-><sceneId>`, `first:`/`last:` (H3 frames), `out:<sceneId>-><takeId>`, `vref:<takeId>-><sceneId>`, and into folder nodes `save:<takeId>-><folderId>` / `autosave:<sceneId>-><folderId>` (see `edgeId`/`parseEdgeId`).
- Wires: a plain click on a wire cuts it (`lib/canvasPrefs.ts` pref `clickToCut`; decided in `CanvasView.onWireClick` in the capture phase with the pure `wireFx.isWireClick`/`wireClickAction`: never `out` wires, never after a drag/pan/pinch, Ctrl/Shift+click selects). Every cut goes through `edges.cutEdge` → `actions.announceWireCuts` (also `deleteSelection`) BEFORE the store change so `Wires.tsx` `WireCutLayer` can animate a ghost copy; `WireConnectionLine` is the line drawn while dragging (valid/invalid via `wireFx.wireVerdict`, end snaps to the target handle). New wires draw in once (`wireFx.markFreshWires` from the raw-edge diff). Pref `animations` ('full' | 'reduced' | 'off', `useMotionLevel` also honours the OS reduce-motion) → `.cv-stage[data-motion]`; styles in `components/canvas/wires.css`.
- Saving videos: `Take.fileName` ("Tên file", `core/fileNames.ts` sanitizes; `actions.takeFileBase` / `renameTake`) is used by every save; without one, `actions.defaultTakeFileBase` renders the "Cách đặt tên file" template (`core/nameTemplate.ts`, pref `nameTemplate`, default `{scene}_{take} - {title}` = "S03_T2 - title"; empty tokens drop their separator). `lib/downloads.ts` pref `askWhere` ("Hỏi nơi lưu & tên file": desktop native dialog via `lib/desktopFiles.ts`, Chromium save picker, else download + toast). Folder nodes ("Thư mục"): data `Project.folders` (`core/folders.ts`, undoable wires), commands + auto-save of finished takes in `src/folderActions.ts`, writing in `lib/saveFolders.ts` (desktop IPC `files:*` / web directory handle per folder id). `electron/main.cjs` only writes into folders the user picked (allowlist in userData; pure `<save-rules>` block tested by `src/lib/__tests__/saveRules.test.ts`: only the file types SanoVids makes, the save dialog adds only a `.txt`, writes go through a `.part` file, never overwrite). Saves that wait for a folder (and saves being written) are kept per browser in localStorage `bdp:folder-waiting` (`saveFolders.waitingTakes` / `markWaiting`) and written by `folderActions.refreshFolderNode` once the folder is writable again. Choosing the folder again (`project.setFolderPlace`) is not an undo step. Folder node ids are per project: Duplicate / import give new ids; an exported `.sanovids.json` and an import carry no folder path (`persist.projectForExport` / `importedProject`). Deleting takes / scenes drops their folder links (`core/folders.dropFolderLinks`).
- Settings (`components/dialogs/SettingsDialog.tsx`): "Cơ bản" / "Nâng cao" + search (`settingsSearch.ts`, accent-free, both levels). Rows are declared once in `GROUPS` (label/hint feed the row and the search); row components in `SettingsBasic.tsx` / `SettingsAdvanced.tsx` subscribe to one pref each. Every pref store validates what it reads (`lib/theme`, `lib/downloads` `parseDownloadPrefs`, `lib/playback`, `lib/canvasPrefs`, `store/ui` `parsePref`, `providers/mock` `parseMockSettings`). `lib/settings.ts` = the list of device prefs: `currentSettings`, `applySettings`, `resetAllSettings` (+ `restoreSettings` for Hoàn tác), settings file export/import (`readSettingsFile` / `sanitizeSettings`, value by value; never the provider, the download folder or projects). New prefs: `toastTime` (store/ui, scales every toast), `zipPrompts` and `nameTemplate` (lib/downloads). `initMotion()` (main.tsx) mirrors the `animations` pref + OS reduce-motion on `<html data-motion>`; `styles/app.css` applies 'reduced' / 'off' app-wide. Panel layout reset: `PanelResizer.resetPanelLayout` / `restorePanelLayout`.
- About (Settings → "Cơ bản" → "Giới thiệu", the LAST `GROUPS` entry, no pref): `AboutBlock` in `SettingsBasic.tsx` (logo tile `.dg-about-*`, version line, author "Nguyễn Giang Minh (Jame Steven)", partner line "Đồng hành: Sano Group" — Sano Group is never presented as the developer —, copyright, license note, signature status, thumbprint, "Mở trang tải về" via `lib/updates.openReleasePage`). Every user string lives in pure `src/lib/aboutModel.ts` (`signatureView`, `versionLine`, `formatThumbprint`; the official thumbprint is `sanovids.signers[0]` via a NAMED import from package.json — never import `build` or the whole object). `src/lib/appSignature.ts`: strict `parseAppSignature`, store `useAppSignature` (select `sig` only), idempotent never-throwing `loadAppSignature` (source 'desktop' = `bdpDesktop.app.signature()`, 'none' = desktop build without it → unknown, 'sim' = `providers/dev/appSignature.ts`, driven by DevPanel "Cập nhật" → "Chữ ký số (Giới thiệu)"; `devUpdates.failSignature()` simulates the update error `signature`).
- Logo / icons: `components/common/Logo.tsx` (inline SVG, `currentColor`, aria-hidden unless `title`) in the top bar `.tb-logo` tile and the About tile; brand tokens `--brand-plate-top` / `--brand-plate-bottom` / `--brand-ink` are defined once, in the dark `:root` block only (same value in both themes; tile = gradient top→bottom, ink colour, radius 22%). App / installer icons are generated (`npm run icons` = `scripts/make-icons.mjs`, devDependency `@resvg/resvg-js`): `win.icon` = `build/icon.ico`, NSIS bitmaps in `build/`, window icon `dist/icons/icon.ico` on win32.
- Storyboard reorder: drag a card (mouse past 5px, touch long press) or Alt + arrows → `moveScene` (one undo step, codes renumber; "Phát liền" and the .zip follow scene order). `components/views/useCardReorder.ts` runs the gesture outside React (inline transforms + `data-reordering`/`data-dragging`/`data-slide`/`data-landed`, no card re-renders), live-shifts the other cards, auto-scrolls, and slides cards (FLIP) on every order change incl. undo; pure math (hit test, shifts, keyboard steps, auto-scroll) in `storyboardOrder.ts`. Honours the `animations` pref via `.vw-sb-root[data-motion]` ('reduced' = insertion bar, no slides).
- Auto-update (docs/UPDATES.md). Feed: `package.json` `build.publish` (github, JameSteven404 / public repo `sanovids-releases`, no token, never `private`/`channel`) → electron-builder writes `resources/app-update.yml`, which MUST contain `publisherName` (it comes from `build.win.signtoolOptions.publisherName`; never set `win.verifyUpdateCodeSignature`, which drops it; `tidy-release` warns and `release:check` fails without it); the app only reads that (no `setFeedURL`, no token, the renderer never sends URLs/paths/versions). Main: `electron/updater.cjs` (electron-updater wiring, IPC `updates:getState|check|download|install|setPrefs|openReleasePage` + push `updates:state` to the main window only, schedule 15 s after ready-to-show then `checkDue` every 10 min = 4 h / 30 min after offline, logger `userData/logs/updater.log`, prefs + install attempt in `userData/updater.json`) and pure `electron/updater-rules.cjs` (no npm requires; reducer, kinds, error mapping to fixed Vietnamese texts, notes → plain text, profile dir; tested by `src/lib/__tests__/updaterRules.test.ts`). Signed-update pinning: `updater.cjs` installs ONE pinned verifier (`signature.checkFileSignature` against `readSignerPins()`) as both `autoUpdater.verifyUpdateCodeSignature` and an instance override of `autoUpdater.verifySignature` (electron-updater 6.8.10 `NsisUpdater.doDownloadUpdate` calls it; its own version skips everything when `publisherName` is missing), asserts both are installed and pins exist (else downloads are refused, code `signature`), re-verifies on `update-downloaded` before dispatching 'downloaded' (failure → delete the file, `autoInstallOnAppQuit = false`, remember the version in the in-memory per-launch `rejected` set so auto-download skips it; manual `updates:download` still retries) and before every `updates:install`; `onQuit` installs only when the installer is still the verified file (`rules.sameVerifiedFile`: path + size + mtimeMs, synchronous). `mapUpdaterError` maps `ERR_UPDATER_INVALID_SIGNATURE` to 'signature' before the offline / HTTP / checksum / disk tests; the text is `ERROR_TEXT.signature` = `UPDATE_ERROR_TEXT.signature` (dialog: "Mở trang tải về" + "Thử lại"; `updateActions` toasts a signature refusal once per version with "Trang tải về", also when it ends a restart — never the "install failed" toast; Settings "Xem chi tiết" (`hasUpdateDetails`) reaches that dialog). A known update stays `available` through re-checks (a failed one never hides it). The install-on-quit attempt is recorded in the app `quit` event (exit code 0, like electron-updater; never for a vetoed quit); a launch < 2 min after it keeps the attempt (`startupAttempt`); main's 18 s watchdog after `quitAndInstall` reports a failed install. Kinds: `installer` (download + install; quitting with an update ready installs it), `portable` (check only → "Tải bản mới" opens the release page), `dev` (unpackaged: unsupported). `electron/preload.cjs` → `window.bdpDesktop.updates` (contract `src/lib/updateTypes.ts`). Renderer: `lib/updateModel.ts` (pure texts / pill / dialog view), `lib/updatePrefs.ts` (device pref `bdp:pref:updates` `{ autoDownload }`, in settings export/reset; NOT `downloads.autoDownload`), `lib/updates.ts` (bridge + mirror store), `src/updateActions.ts` (toasts, install flow: hold new submits → wait sends ≤ 15 s → flush prompt drafts + autosave → install; never while "Nhập prompt" is open; "Cập nhật khi xong" countdown, counting `runs.restartWork` = queued takes of existing scenes + running ones), top-bar `UpdatePill`, dialog kind 'update' (`UpdateDialog`), Settings group "Cập nhật", DevPanel tab "Cập nhật" driving `providers/dev/updates.ts` (simulated bridge, only outside Electron). Release tooling: `scripts/update-notes.mjs` (CHANGELOG section → gitignored `build/release-notes.md` → latest.yml notes, run by `dist:win`), `scripts/tidy-release.mjs` (keeps latest.yml + current blockmap in `release/_build`, warns on a wrong feed or a missing `publisherName`), `scripts/publish-release.mjs` + pure `scripts/releaseLib.mjs` (tested in `scripts/__tests__`): checks, then draft → upload → verify SHA-256 → publish, private `sanovids` first, public `sanovids-releases` LAST; `--dry-run` = `release:check`; group (j) "Chữ ký số" (`scripts/buildInspect.mjs`) re-verifies signatures + timestamps, VersionInfo, the fuse wire, app-update.yml and `build/signing/SanoVids-NguyenGiangMinh.cer` (uploaded with the installers). Never add a script named `release` (electron-builder auto-publishes). Test-only isolation: env `SANOVIDS_PROFILE_DIR` or `sanovidsTestProfileDir` baked into a test build's package.json via `extraMetadata` (never in the real package.json) moves userData out of `%APPDATA%\SanoVids`; invalid (incl. Windows aliases: UNC / `\\?\`, trailing dot / space, 8.3 `~`, streams, parents of the real folder, links via realpath) → exit 2. Never `electron .` / a packaged run without it during agent tests, and test installers need their own appId / productName / executableName.
- Signing & hardening (docs/SIGNING.md). Release .exe files are signed by electron-builder `build.win.signtoolOptions`: `certificateSha1` = the author's self-signed cert (`CN=Nguyễn Giang Minh (Jame Steven), C=VN`, `7489ABFAC1A7CD23D5FFB0785CA7CAB414AE49ED`, valid to 2036-10-03) in `Cert:\CurrentUser\My`, one SHA-256 signature, RFC 3161 DigiCert timestamp, explicit `publisherName`; `forceCodeSigning: true`; `signExts` names Electron's 4 unsigned DLLs (ffmpeg, vk_swiftshader, vulkan-1, dxcompiler). A missing cert fails the build ("Cannot find certificate"). The build log shows "Nguy?n" (child PowerShell codepage): cosmetic, the packaged files carry correct UTF-8. Never add `certificateSubjectName`, `signtoolOptions.sign`, `certificateFile`/password, `toolsets.winCodeSign`, `win.verifyUpdateCodeSignature`, `asar: false`, `asarUnpack`, `disableAsarIntegrity`. Author pitfall: electron-builder's normalizePackageData turns `author` "Nguyễn Giang Minh (Jame Steven)" into name "Nguyễn Giang Minh" + url "Jame Steven", so `build.extraMetadata.author.name` re-sets it after normalization (CompanyName / uninstall Publisher); `extraMetadata` arrays are UNIONED (a test build adding a pin ships [REAL, TEST]); tested by `src/lib/__tests__/buildConfig.test.ts`. Trusted signers = top-level `package.json` `sanovids.signers` (thumbprints; NOT under `build`, which is stripped from the packaged package.json; protected inside app.asar by asar integrity). Rotation: add the new thumbprint in a release still signed with the old cert, ship it, then switch signing — well before 2036-10-03 (the chain is built at the current time, so an expired cert becomes `bad-chain`). `electron/signature.cjs` (never requires 'electron', so main, updater and scripts share it): `readSignerPins`, `checkFileSignature` (System32 powershell.exe, `-NoProfile -NonInteractive -InputFormat None -Command <SIGNATURE_SCRIPT>`, no `-EncodedCommand` / `-ExecutionPolicy Bypass`, path only via env `SANOVIDS_SIG_PATH`, 60 s, never rejects). Pure rules in `electron/updater-rules.cjs` (still no require): `SIGNATURE_SCRIPT` (one line, no `"` / newline / backtick, ASCII-escaped JSON between `SVSIG` markers), `parseSignatureOutput`, `judgeSignature` decision table in order: no pins → unknown/no-pins; bad output → verify-failed; status 2 → unsigned; status 3 → tampered (checked BEFORE the thumbprint: a modified file still reports the pinned signer); not Authenticode → verify-failed; thumbprint ∉ pins → other-signer (a same-CN impostor lands here); ok only for status 0 with chain flags ⊆ [UntrustedRoot], or status 1 + 0x800B0109 + chain exactly [UntrustedRoot] of length 1; anything else → bad-chain. Never decide on StatusMessage / Subject (localized). Tested by `src/lib/__tests__/signature.test.ts`. Self-check: main checks `process.execPath` once, 3 s after ready-to-show, memoized; IPC `app:signature` (fromApp only; payload `hardening-rules.appSignaturePayload`) → preload `bdpDesktop.app.signature()` (inserted before `canvasapp:`; `updates:` stays the LAST preload key) → About. Fuses (`build.electronFuses`): RunAsNode, NodeOptions, NodeCliInspect, GrantFileProtocolExtraPrivileges off; EmbeddedAsarIntegrityValidation + OnlyLoadAppFromAsar on (a modified app.asar does not start → reinstall); CookieEncryption deliberately OFF (enabling migrates the cookie store one way: never turn it on and then off). `electron/hardening-rules.cjs` (pure, no requires, `hardeningRules.test.ts`): packaged builds refuse debug / security-off switches (`refusedSwitches`, queried with `app.commandLine.hasSwitch` only, fail closed) with a dialog + `process.exit(3)` before userData is touched; remote-debugging switches only with an env or baked test profile; `allowDevTools` (unpackaged or test profile) gates `devTools: DEVTOOLS` on the main, login and checkout windows and the F12 / Ctrl+Shift+I handler; `app.enableSandbox()`; `will-download` allowlist (`blob:app://bdp/` + mp4 webm mov m4v jpg jpeg png webp svg txt zip json, must cover main.cjs SAVE_ALLOWED_EXT); default-session permission allowlist (clipboard-sanitized-write, fileSystem, fullscreen; device permissions denied); no `<webview>`, Bluetooth selection denied; canvasapp login popups keep the https-only window-open handler recursively; CSP header on every `app://bdp` HTML response (`script-src 'self'` + the sha256 of index.html's inline theme script, computed from dist/index.html at runtime; a new inline script / eval / external origin needs a CSP change). Release builds go through `scripts/electron-build.mjs`: `ELECTRON_BUILDER_DISABLE_BUILD_CACHE=true` (fuses are not part of the exe cache key), refuses `ELECTRON_BUILDER_OFFLINE` (silently drops timestamps) and any run without `--publish never`. Key backup / restore: `scripts/signing/sao-luu-khoa-ky.ps1` / `khoi-phuc-khoa-ky.ps1`; user trust script `tin-cay-chung-chi.ps1`; public download-page repo content in `scripts/releases-repo/` (pushed by hand). Never export the private key, never change certificate trust on a dev machine during tests (test certs are openssl files, signed with `/f`).

## Conventions
- UI text in Vietnamese; model names stay English (Seedance 2.5, MiniMax-H3).
- zustand v5: a selector must return a stable value. Select primitives / existing objects, or wrap derived arrays/objects in `useShallow` (`zustand/react/shallow`). Never `useStore(s => s.list.filter(...))` without `useShallow` — it loops forever.
- Styling: plain CSS files next to components, using tokens from `src/styles/base.css` (`--panel`, `--accent`, `--ref`, …) and shared classes (`.btn`, `.btn-primary`, `.icon-btn`, `.input`, `.select`, `.textarea`, `.badge`, `.chip`, `.kbd`, `.empty`, `.section-title`, `.status-dot.<status>`, `.progress`). Prefix component classes per area: `cv-` canvas, `sb-` sidebar, `in-` inspector, `rq-` runs/queue, `vw-` views, `dg-` dialogs, `tb-` top bar, `tu-` top-up, `dv-` development mode (components/dev). Never use a bare utility name (`progress`, `ok`…) as a modifier class: `.progress` is the global progress bar.
- Shared components: `components/common/Modal.tsx`, `Toasts.tsx`, `Media.tsx` (`MediaImg`, `AssetAvatar`, `AssetChip`).
- Development mode UI (`components/dev/`): `DevPanel.tsx` ("Bảng phát triển", dialog kind 'dev', `actions.openDevPanel(tab)`), `DevSheets.tsx` (simulated login / SePay sheets mounted at the App root above dialogs, `data-top-overlay`), `devModel.ts` (pure texts / fault catalog / log filter / "Kiểm tra nhân vật", tested). User-facing wording: "Phát triển" / "DEV" / "credit dev"; "demo" only for legacy mock takes ("Demo cũ").
- Dark (default) and light themes (`lib/theme` pref 'system' | 'light' | 'dark'; light tokens under `:root[data-theme='light']`, so every colour must be a token). Keep it fast with 100+ scenes: memoize node components, avoid subscribing big components to the whole project.
- Working tree is LF (`.gitattributes` `* text=auto eol=lf`); only `.bat` files are CRLF. `LICENSE.txt`, `build/license_vi.txt`, `scripts/releases-repo/LICENSE.txt` (byte-identical) and the signing `.ps1` scripts are UTF-8 with BOM (the NSIS license page and Windows PowerShell 5.1 need it): keep the BOM.
- Author / copyright strings are exactly "Nguyễn Giang Minh (Jame Steven)" and "© 2026 Nguyễn Giang Minh (Jame Steven) · Đồng hành: Sano Group" (NFC). Sano Group is credited only as the partner ("Đồng hành"), never as the developer.
- Never add a `beforeunload` handler in desktop code: it silently cancels `quitAndInstall` (the update never installs). Release notes / update data are rendered as text only (no `innerHTML` / `dangerouslySetInnerHTML`).
