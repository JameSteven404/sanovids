# SanoVids — architecture (0.6.0 work in progress)

Node-canvas app for producing AI films scene by scene (replacement concept for canvasapp.io.vn).
React renderer + Electron desktop (Windows; experimental Apple Silicon Mac build). Development mode uses the real gateway against an in-app simulation (`src/providers/dev/`, no network, fake "credit dev"). It is open in source/test builds, locked in release builds until an owner unlock; while locked, new takes use the real canvasapp gateway only after explicit opt-in. Saved legacy mock takes remain supported.

## Run
- `npm run dev` → http://localhost:5180 (or double-click `start.bat`)
- `npm run typecheck`, `npm test` (vitest), `npm run build`
- `npm run dist:win` (signed installers into `release/` through `scripts/electron-build.mjs`; needs the author's signing key in `Cert:\CurrentUser\My` and network for timestamps; scratch/test builds: `npx electron-builder … --publish never -c.directories.output=<dir>` with `ELECTRON_BUILDER_DISABLE_BUILD_CACHE=true`, never into `release/`), `npm run release:check` / `npm run release:publish` (owner only, docs/UPDATES.md), `npm run icons` (all icon files from `build/icon-source/*.svg`)

## Stack
Vite 8 + React 19 + TypeScript 7 (`tsc` is the native compiler) + `@xyflow/react` 12 (React Flow) + zustand 5 + zundo (undo/redo) + lucide-react 1.x + idb-keyval + jszip. Desktop: Electron + electron-builder + electron-updater (desktop main process; the ONLY runtime dependency — renderer libs are devDependencies because Vite bundles them).

## Architecture (read before editing) — schema v2, see docs/SPEC-v2.md
- `src/core/types.ts` — schema 2. `Scene.refs` = ordered asset ids; each asset's pictures produce `@image_N` slots. Reference videos are retired: `Scene.videoRefs` stays empty for old readers; `legacyVideoRefs` / `Take.legacyVideoRefsSnapshot` preserve inert history. `src/core/migrate.ts` moves old links there and still upgrades v1 data (prompt blocks → prompt text); duplicate/import drops archived links, never rewrites prompt text. No prompt blocks, automatic references paragraph or scene→scene continuity link.
- `src/core/compile.ts` — pure prompt compilation (text as written, legacy @Tag conversion), `parseTokens`, `imageSlots`, `tokenForAsset`, `remapTokens`. Image-slot edits preserve identity in one undo step; only a pure append preserves typed-ahead numbers. A removed token's fallback text never holds an "@" and is spaced off an open "@…" before it (`fallbackGap`: "@image " + "3 chị em", "@Lu" + "mi", "@image_1" + "3" never form a token / mention / placeholder). Queue requests use `Take.imageKeysSnapshot` captured with `promptSnapshot`, never live refs (`src/__tests__/characterSync.test.ts`). `retiredVideoTokens` finds old @video spellings, including labelled placeholders: `compiled.retiredTokens` / `unsentTokens`, every highlighter and `providers/canvasapp/mapping.ts` `validateRequest` reject them. `src/videoRetired.ts` supplies explicit undoable text fixes and the once-per-project notice; never silently remove old @video text.
- `src/core/models.ts` — model capabilities, credit pricing, `costOf`, `normalizeSettings`. No reference-video capability or request media; retained old token spellings are validation input only.
- `src/core/runRules.ts` — ONE `runBlock` / `runBlockReason` rule list: newer-build markers → empty/long prompt → missing images/frames → retired @video text → labelled placeholders (`waitingReason`) → wrong glued labels (`mismatchReason`) → other unsent image tokens → `settingsBlock`. `isRedTextBlock` drives the node's red-text status. Cached `compiledOf` / `sceneRunBlockReason` serve stable selectors; `components/runs/shared.tsx` `useSceneRunBlock` and `useSettingsRunBlock` share this with `store/runs.ts` `check()`. Every Run (node, inspector, selection) only opens the run dialog (`actions.requestRun` → 'runConfirm'), which lists refused scenes ("Bỏ qua: …"). `src/core/runGate.ts` is positional wrappers only. Firm provider limits alone block; old/fallback limits warn.
- `src/store/project.ts` — undoable project store (zundo). Image-ref edits and token remapping share the undo step; `withMedia` uses labelled placeholders on removal even with auto-renumber off. `LAYOUT`, `ROW_H`, `defaultTakePosition`: scene rows with takes to the right. `src/core/placeholders.ts` (`removalLabels`, `planFill`, `planReplace`, `labelFitsSlot`, `assetDeleteImpact`) + `src/core/tokenLabels.ts` (`sanitizeLabel`): removed images become `@image_?N(label)`, never lost words. Names/tags + picture index identify the label; NFC, ≤ 40 code points + ellipsis. Deleting a placeholder's "?" by hand still requires its label to match the current slot. Store `fillPlaceholder` / `fillPlaceholders` / `fillPictureSlot` / `replaceRef`, commands `src/placeholderActions.ts`: explicit fills only, one undo step; refused fills change nothing. `components/inspector/PlaceholderBar.tsx` appears on node and panel; `tokens.ts` `segmentForScene` / `segmentPrompt` share red marks across static/live editors and previews. `src/core/staleTokens.ts` supplies removal toasts and stale-number warnings.
- `src/store/runs.ts` — takes (`Take.position`) + non-undoable job queue. `removeTakes` drops folder links, never prompt text; deleted scenes' takes remain in the queue but leave the canvas. A take dropped / wired on a scene (card, prompt editor, wire) links nothing: `actions.refuseTakesAsReference` toasts why. Cancel while sending (PAY-H, docs/GATEWAY-CANVASAPP.md "Huỷ lúc đang gửi"): a take whose POST may have reached canvasapp keeps `submitUnknown` from the click on (provider `mayHaveSent`, synchronous); one still before its POST stops at the next `checkCancelled()` unmarked; `requestInFlight` makes "Chạy lại" wait; `lateOutcomes` write results that land after a project switch back; `isUncertainSubmit` takes survive "Dọn" (`clearableTakes`) and ask before deletion (`core/deletePlan`); the run dialog warns (`maybeBilledRunWarning` / `paidCancelledRunWarning`). `createSceneFromVideo` makes a new scene with an empty prompt and usable take image/settings snapshots (falls back to the source scene when unknown); no video reference.
- "Nhập job" (reverse sync, docs/GATEWAY-CANVASAPP.md §4): jobs made on canvasapp's page on a bridge node → takes. Read-only (GET). Pure rules `providers/canvasapp/siteJobs.ts` (`classifySiteJobs`, `sentMayOwn` = never a job an unanswered POST may own, hints → `reconstructSiteJob` known / `inferred` "≈" / `unknown` "?" — hints only for the newest run of a node, `hintsSuperseded`; a damaged saved `Take.imported` becomes a marker with every field unknown, never dropped); adapter `scanSiteJobs` / `siteJobPrompts` / `claimSiteJobs` → ledger `imported` (never posted; `findJob` skips every imported job); `src/siteJobActions.ts` (project pinned, ≤ 20, through `gatewayProvider(pid)` = the registry instance); `useRuns.importTakes` (born `processing` + `remoteId`, `Take.imported`, never a submit slot; "Chạy lại" = new take); UI `components/runs/ImportJobsDialog.tsx` (dialog kind 'importJobs', `back`, `provider`: the Bảng phát triển always reads the simulation), `importJobsModel.ts`, display helpers `importedTake.ts` (every settings / cost / restore place; `restorePlan`: references restored with the mode they need, else the scene keeps its own; old @video text remains blocked). Dev: `devServer().createSiteJob` (`providers/dev/siteClient.ts`, shared with the e2e fake), DevPanel card "Tạo job như trên trang canvasapp".
- `src/providers/index.ts` — registry: `effectiveProvider`, `activeProviderId` ('dev' | 'canvasapp', never 'mock'), `activeGateway` (THE path for balance, login, top-up and credit history: the simulation in development mode, never the network), `gatewayProvider`; `useProviderPrefs` preserves the saved choice across locks. `selectableProviders()` hides dev while locked; `providerBlockedReason` gates new submissions and unknown DEV retries. Locked = effective 'canvasapp', but `CANVASAPP_NEEDS_OPT_IN` blocks it until explicitly chosen; never silently fall back to simulation. `getProvider('dev')` still polls existing jobs. `providers/dev/` uses the real adapter over `bridge.ts` / `server.ts` (own storage, credit dev, faults, simulated login/checkout sheets); `resetDevMode` resets both. `dev/routes.ts` = main.cjs's `<canvasapp-routes>` allowlist ported: keep both in sync (`dev-server.test.ts` runs main's block next to it); `dev/validate.ts` = canvasapp's strict request validators, shared by the dev server and the e2e fake. See docs/SPEC-v2.md §11.
- SANO gateway (D216 TH-15): `src/providers/sano/gateway.ts` (pure core, injected fetch / token / blobs; contract at the top: same-origin `/api/video`, idempotencyKey = take id so a resend never makes a second job, Bearer token only (no cookie auth); `tokenState()` 'none' / 'refused' (this token got a 401 — never its JWT exp: the PC clock may run ahead) / 'ok', read from the gateway's creation inside SANO (made at registry init in the SANO build), on each request and every 3 s (a failing host `token()` = a read with no token) → `blockedReason()` = `providerBlockedReason('sano-gateway', account)`: 'refused', or 'none' once a first read ended → `SANO_LOGIN_TEXT` (the Run refusal; a waiting take says `SANO_LOGIN_WAIT`), a take bound to another account (`Take.account` = token sub as `accountKey`, bound at enqueue to the last read, then to a read started at ▶ (`freshAccount`; the takes start once it ends), else in `submitTake` / `recoverTake`) → `SANO_OTHER_ACCOUNT` (waiting: `SANO_OTHER_ACCOUNT_WAIT`); such takes are parked (`store/runs parkedReason` / `cannotRunHere`: no request, download or cancel, no lock, no refs read, never failed — but one whose own POST / download is out keeps the engine and the lock) and shown in the queue (`parkedReasons`: bar chip + banner, `parkedCountText` names what they wait for); the engine wakes on the gateway's `useProviderLimits` bump; a job request whose token names another account than the engine chose for → 'deferred' before sending, refs ≤ 20 MB base64 → 'too-large' before any request, 2 result downloads at once (each held whole in memory; another → 'deferred', asked again), an older token read answering after a newer one dropped, cancel only while queued, `/capabilities` cached 10 min → `capabilities` / `settingsLimits` — a take queued while SANO says 'simulator' (`Take.expectSimulated`) is POSTed with `expectMode: 'simulator'` and refused (`SANO_NOW_LIVE`, never uncertain) on SANO's 409 `{ mode }` (nothing created; an earlier job of its key is still answered first); a look-up's 5xx / lost connection is 'deferred', asked again after a poll interval (`store/runs recoverAt`)) + `sano/index.ts` (browser wiring). On only inside the SANO app (`sanoGatewayAvailable()`: a `VITE_SANO_GATEWAY=1` build in a same-origin iframe, never in a plain tab; `window.__SANO_GATEWAY__` only gives the token): the choice follows the build (`sanoBuild()`: a plain tab of it picks 'sano-gateway', refused with `SANO_UNAVAILABLE`), `effectiveProvider` picks 'sano-gateway' when chosen or locked on the web; Electron keeps canvasapp. `creditKindOf('sano-gateway')` = 'canvasapp' (real money, no demo wallet); the credit pill hides; Settings / queue drawer show a SANO note. Other run texts still name canvasapp (follow-up).
- Gateway bridge / account safety: `src/providers/canvasapp/adapter.ts`, `mapping.ts`, `api.ts`, `transport.ts`. `sceneNodeKey` / `canvasNodeId` identify a scene OF A PROJECT; do not change their hashes (legacy nodes and retries keep their original ids). `adoptBridgeCanvas` reads a bridge found by name before PUT; `keepRunningNodes`, `adoptedKey`, `entryNodeId` preserve running/read-back nodes without duplicates. Unreadable canvas → nothing saved or submitted. `noteAccount` (hashed e-mail from `/api/me`) resets bridge state on account change, keeps the ledger; `sessionEpoch` prevents an old submit writing or posting after reset (`SESSION_CHANGED_TEXT`).
- Double-charge proof (`adapter.ts`): synchronously persist AND read back `sent[key]` before every POST; failed storage → no POST. Known `jobs` / `imported` keys never post. Read jobs before each POST; `beforeAt` is request-start minus `gatewayListCacheMs`, never response arrival (main 15 s / dev 2 s). `findJob`: several exact client_request_id matches belong to the same take, follow one (`sameKeyJob`); without client_request_id it skips jobs that are known or imported, listed before the POST, on another node, of another model / duration / creation mode, or outside `siteJobs.inPostWindow`. A remaining candidate a rival unanswered POST on that node may own (`rivalsOf` / `mayBeJobOf`, `SETTLE_MS`), several candidates, or one it cannot tell apart (no node id, no time) → 'ambiguous', NEVER 'none' and never resent — never filter such candidates out. 'none' only when `listCovers` proves the list reaches back to the request: unchanged ended anchors (status + finished_at), recent coverage, or an empty list with no prior evidence; else 'unlisted'. (`sentMayOwn` is the Nhập job / `claimSiteJobs` rule, not findJob's.) A lost reply gets two fresh lookups 15 s apart (`RECONCILE_DELAYS_MS`; 'ambiguous' stops at once, otherwise the last readable look decides) and at most one automatic resend with the SAME body/key, only after 'none' and a newly stored record. Truncated/unreadable history, another bridge, `dropped`, or `retryOfUnknown` without a record → `uncertain` / `unverifiable`, never automatic new-key retry. A recent rival → `deferred` (`RIVAL_SETTLING_TEXT`). UI "Tạo lại" explicitly creates a NEW potentially billable take. See docs/GATEWAY-CANVASAPP.md; adapter/e2e tests use fakes, not proof of the live site's deduplication.
- Provider limits: `mapping.profileIssues` is the submit/UI rule over the adapter's one `/api/video-profiles` cache. Prices come from the same read: `mapping.profilePrice` (`options.pricing[resolution][seconds]`, like canvasapp's Run button) → `SettingsLimits.price` → `providers/limits.takeCost` (else `core/models.costOf`) = every pre-run cost (cards, inspector, presets, menus, run dialog, `Take.cost`; hook `runs/shared.useTakeCost`, `sidebar/shared.totalCost(scenes, limits)`); dev `DevConfig.pricePercent` ("Bảng giá của canvasapp") scales the simulated table and its charge. `settingsLimits`, `limitsInfo`, `refreshLimits` (10 min firm TTL; force limited to 5 s; `changed` reads after login immediately, after any in-flight read). Failed UI refresh preserves a fresh good list. `watchProviderLimits` renews 30 s before expiry; `useProviderLimits` selects `rev[id]`, `getProvider` never bumps it. Inspector `components/inspector/settingsLimits.ts` / `components/runs/shared.tsx` use the same refusal; stale/fallback data only warns.
- Chunked downloads: `transport.download` → IPC `canvasapp:downloadOpen|downloadRead|downloadClose`; `/stream` is refused through ordinary `canvasapp:request`. `electron/main.cjs` pure `<canvasapp-downloads>` / `<canvasapp-net-get>` blocks (`createDownloadSessions`, HTTPS-only manual redirects via net.request): one lane per connection, ≤ 4 MiB pieces, 1 GB cap, 60 s idle / 10 min pull-idle / 60 min connection. Resume only with a retained strong validator and matching Range/If-Range 206; cut bodies never finish. Transport keeps pieces on resumable reopen failures, permits one restart from zero, caps repeated opens. Cancel/loadRuns abort through `fetchAborts`; committed navigation, crash, close and logout close sessions. `store/takeTransfers.ts` displays progress; `remoteVideoReady`, `actions.cancelTake` and `deletePlan.checkTakeDelete` warn before dropping a paid download. Dev `downloads.ts` ports the main block (64 KiB / 10 s / 2 min), parity-tested in `gatewayDownloads.test.ts`.
- Keep-login: `electron/keeplogin-rules.cjs` + `main.cjs` restore a safeStorage-encrypted copy of canvasapp's own session cookies before the first request (≤ 30 days from login/cookie renewal; ordinary use never extends it). Default on for installer/source/Mac Applications, off for Portable/other Mac placements; an unset default off never deletes the copy (Setup and Portable share userData: `keepLoginCopyRule` 'leave', factory dep `chosen`) — only an explicit off, logout, expiry, a damaged file or a refusal of a copy that run restored/wrote. No Cloudflare/Google/SePay cookies or plaintext; confirmed login separately clears Google account cookies. Explicit rejection deletes the copy. Logout deletes first, keeps BOTH `canvasappDownloadsBlocked` and `canvasappLoggingOut`, then `drainCanvasappRequests` aborts/awaits API and download requests (5 s cap); an old in-flight save cannot recreate it. Never log cookie values (only `keepLoginRules.cookieShapeLine`). IPC `canvasapp:keepLogin` / `setKeepLogin` stays inside preload's canvasapp block. Dev `providers/dev/keepLogin.ts` / bridge `simulateRestart` model the lifecycle.

The panel's "Khung soạn rộng" and node never edit the same scene concurrently: handoff flushes `lib/promptDrafts.ts`. Draft commits use 160 ms, blur, unmount and lifecycle flushes; Escape commits/closes, Ctrl/⌘+Enter flushes then requests Run. `canvasModel.ts` `LOD_ZOOM` = 0.55: far nodes show a two-line excerpt, no live field; every node and the geometry estimates read it through `NodeSizer.useFarView` (a deferred value: the switch renders in the background), and a scene card that mounts while the canvas moves draws its fixed frame first and its body in a background render (`useBodyReady`, `setCanvasMoving` from onMoveStart / onMoveEnd); the wheel pans by default (pref `canvasPrefs.wheel` 'pan' | 'zoom', Settings "Con lăn chuột"; Ctrl / ⌘ + wheel and a pinch zoom); dragging ONE node snaps its start / centre / end to the other nodes' (`canvasModel.alignToGuides`, `GUIDE_TOLERANCE_PX` 6 ÷ zoom, applied in `onNodesChange` while dragging AND at the drop, never against the auto-placed takes that follow a dragged scene) and `AlignGuides.tsx` draws the lines (`useCanvasLocal.guides`, React Flow `ViewportPortal`); Enter/reveal returns to near view; double-click on empty canvas / "Cảnh mới" while far goes through `typeOnNode` (zoom in, then open the field; canvas letter / Delete keys are held meanwhile). Shared `segmentForScene` + `PlaceholderBar` preserve red-token parity; explicit image drops fill placeholders, or link/insert tokens and place image tiles in one undo step. Inserted tokens (drops, legend chips, "Nối & chèn") never land inside a word, token or red text: `inspector/tokens.ts` `snapToWordEnd` moves past the whole `@image_?N(label)` / labelled-token unit; ONE card dropped right on red text fills that group (`core/placeholders` `groupAtOffset` → the explicit fill path; on the node `fillFromDrop` places the image tile inside the same undo step, before the toast: `fillPlaceholderAction` `inSameStep`), several are inserted after it. ## Conventions
- UI text in Vietnamese; model names stay English (Seedance 2.5, MiniMax-H3).
- zustand v5: a selector must return a stable value. Select primitives / existing objects, or wrap derived arrays/objects in `useShallow` (`zustand/react/shallow`). Never `useStore(s => s.list.filter(...))` without `useShallow` — it loops forever.
- Styling: plain CSS files next to components, using tokens from `src/styles/base.css` (`--panel`, `--accent`, `--ref`, …; floating chrome "viên nổi" = `--glass` / `--glass-blur` / `--hairline` / `--glass-shadow` / `--radius-pill`: top-bar `.tb-pill` clusters on a transparent bar, canvas toolbar / tray — docs/UI-MUOT.md; motion = `--motion-press` 75 ms / `--motion-hover` 120 ms / `--motion-state` 150 ms / `--motion-pop` 180 ms + `--ease-ui`, colour / opacity / transform only — `src/styles/__tests__/motion.test.ts` refuses a size / position transition in the canvas CSS) and shared classes (`.btn`, `.btn-primary`, `.icon-btn`, `.input`, `.select`, `.textarea`, `.badge`, `.chip`, `.kbd`, `.empty`, `.section-title`, `.status-dot.<status>`, `.progress`). Prefix component classes per area: `cv-` canvas, `sb-` sidebar, `in-` inspector, `rq-` runs/queue, `vw-` views, `dg-` dialogs, `tb-` top bar, `tu-` top-up, `dv-` development mode (components/dev). Never use a bare utility name (`progress`, `ok`…) as a modifier class: `.progress` is the global progress bar.
- Shared components: `components/common/Modal.tsx`, `Toasts.tsx`, `Media.tsx` (`MediaImg`, `AssetAvatar`, `AssetChip`).
- Development mode UI (`components/dev/`): `DevPanel.tsx` ("Bảng phát triển", dialog kind 'dev', `actions.openDevPanel(tab)`), `DevSheets.tsx` (simulated login / SePay sheets mounted at the App root above dialogs, `data-top-overlay`), `devModel.ts` (pure texts / fault catalog / log filter / "Kiểm tra nhân vật", tested).
