# SanoVids — demo

Node-canvas app for producing AI films scene by scene (replacement concept for canvasapp.io.vn).
Frontend (web + Electron desktop). New takes run in **development mode** by default: the real canvasapp gateway code against an in-app **simulated canvasapp.io.vn** (`src/providers/dev/` — no network, fake "credit dev"); the real canvasapp.io.vn gateway is opt-in in the desktop app. The old mock demo only runs takes saved before.

## Run
- `npm run dev` → http://localhost:5180 (or double-click `start.bat`)
- `npm run typecheck`, `npm test` (vitest), `npm run build`
- `npm run dist:win` (signed installers into `release/` through `scripts/electron-build.mjs`; needs the author's signing key in `Cert:\CurrentUser\My` and network for timestamps; scratch/test builds: `npx electron-builder … --publish never -c.directories.output=<dir>` with `ELECTRON_BUILDER_DISABLE_BUILD_CACHE=true`, never into `release/`), `npm run release:check` / `npm run release:publish` (owner only, docs/UPDATES.md), `npm run icons` (all icon files from `build/icon-source/*.svg`)

## Stack
Vite 8 + React 19 + TypeScript 7 (`tsc` is the native compiler) + `@xyflow/react` 12 (React Flow) + zustand 5 + zundo (undo/redo) + lucide-react 1.x + idb-keyval + jszip. Desktop: Electron + electron-builder + electron-updater (desktop main process; the ONLY runtime dependency — renderer libs are devDependencies because Vite bundles them).

## Architecture (read before editing) — schema v2, see docs/SPEC-v2.md
- `src/core/types.ts` — domain model. `Scene.refs` (ordered asset ids) = reference images → `@image_N`; `Scene.videoRefs` (ordered take ids) = reference videos → `@video_N`. Canvas wires are only a view of these lists. No prompt blocks, no auto references paragraph, no scene→scene continuity link.
- `src/core/compile.ts` — pure: the prompt is sent as written; token helpers (`parseTokens`, `imageSlots`, `tokenForAsset`, `remapTokens`), validation warnings/notes. Character sync rules: a token with no media in the request (`unsentTokens`: past the model cap, mode without refs, or an `@image_?N` placeholder) blocks the run; `remapTokens` keeps typed-ahead numbers only on a pure append of new assets, otherwise turns them into `@image_?N`. The queue sends `take.imageKeysSnapshot` (captured with `promptSnapshot`), never the live refs — see `src/__tests__/characterSync.test.ts`. `src/core/staleTokens.ts`: warnings when renumbering is off. `src/core/migrate.ts` upgrades v1 data. Tests in `src/core/__tests__`, `src/store/__tests__`.
- `src/core/models.ts` — model capabilities (image/video limits), credit pricing, `costOf`, `normalizeSettings`.
- `src/core/runGate.ts` — pure `runBlockReason`: the ONE list of run blockers (store `check()`, SceneNode Run, inspector TakesSection; same order and texts). `@video`: only `compiled.videos` count (leftover refs of H3 t2v / transform never block), against the gateway's `capabilities(model).maxRefVideos` (UI hook `runs/shared.useGatewayRefVideoCap`); canvasapp + dev = `providers/capabilities.CANVASAPP_MAX_REF_VIDEOS` = 0 (no evidence canvasapp takes videos: docs/canvasapp-api-notes.md "Reference videos"); over the cap = refused (`NO_VIDEO_REFS_REASON`), never truncated; `mapping.validateRequest` refuses any `req.videos` whatever the cap.
- `src/store/project.ts` — undoable project store (zundo). Every refs/videoRefs change renumbers prompt tokens in the same undo step. `LAYOUT`, `ROW_H`, `defaultTakePosition`: one scene per row, its takes to the right.
- `src/store/runs.ts` — takes (= video nodes on the canvas, `take.position`) + the job queue engine (not undoable). `removeTakes` also drops them from every scene's videoRefs.
- `src/providers/` — `index.ts`: registry, `activeProviderId()` ('dev' | 'canvasapp', never 'mock'), `activeGateway()` (api + bridge of the dev or real gateway — balance, login, top-up, history all go through it), `resetDevMode()`. `canvasapp/`: the real gateway (api, adapter, mapping, transport); bridge video node = scene OF A PROJECT (`JobRequest.sanovidsProjectId`, `mapping.sceneNodeKey` → `canvasNodeId`, never change the hash: legacy bare-scene-id nodes keep running jobs and pinned re-sends, `adapter.nodeKeyFor`); remembered entries = what is on the last canvas; `findJob` never takes a job another unanswered POST on the same node may own (next to one, the job list is read right before posting — `before`/`beforeAt`, unreadable → not sent; `SETTLE_MS`). `dev/`: development mode — `server.ts` (simulated canvasapp, faults, persistence), `bridge.ts` (simulated electron gateway), `prompts.ts` (login / SePay sheets), `log.ts` (request log), `validate.ts` + `routes.ts` (strict rules shared with tests / main.cjs allowlist). See docs/SPEC-v2.md §11.
- `src/store/ui.ts` — selection (scene, asset and take ids), view, dialogs, drag overlay, toasts, `takeDisplay`.
- `src/store/persist.ts` — IndexedDB autosave (+ localStorage emergency backup), project list, export/import `.sanovids.json`. All functions are async. Media blobs: `src/lib/imageStore.ts`.
- `src/actions.ts` — shared commands (linkAssets, linkTakes, ensureAssetToken, createSceneFromTake, deleteSelection, run, copy, zip). UI calls these. Use `undoToastAction()` from the project store for toast undo buttons.
- Edge ids: `ref:<assetId>-><sceneId>`, `first:`/`last:` (H3 frames), `out:<sceneId>-><takeId>`, `vref:<takeId>-><sceneId>`, and into folder nodes `save:<takeId>-><folderId>` / `autosave:<sceneId>-><folderId>` (see `edgeId`/`parseEdgeId`).
- Wires: a plain click on a wire cuts it (`lib/canvasPrefs.ts` pref `clickToCut`; decided in `CanvasView.onWireClick` in the capture phase with the pure `wireFx.isWireClick`/`wireClickAction`: never `out` wires, never after a drag/pan/pinch, Ctrl/Shift+click selects). Every cut goes through `edges.cutEdge` → `actions.announceWireCuts` (also `deleteSelection`) BEFORE the store change so `Wires.tsx` `WireCutLayer` can animate a ghost copy; `WireConnectionLine` is the line drawn while dragging (valid/invalid via `wireFx.wireVerdict`, end snaps to the target handle). New wires draw in once (`wireFx.markFreshWires` from the raw-edge diff). Pref `animations` ('full' | 'reduced' | 'off', `useMotionLevel` also honours the OS reduce-motion) → `.cv-stage[data-motion]`; styles in `components/canvas/wires.css`.

Choosing the folder again (`project.setFolderPlace`) is not an undo step. Folder node ids are per project: Duplicate / import give new ids; an exported `.sanovids.json` and an import carry no folder path (`persist.projectForExport` / `importedProject`). Deleting takes / scenes drops their folder links (`core/folders.dropFolderLinks`).

Feed: `package.json` `build.publish` (github, JameSteven404 / public repo `sanovids-releases`, no token, never `private`/`channel`) → electron-builder writes `resources/app-update.yml`, which MUST contain `publisherName` (it comes from `build.win.signtoolOptions.publisherName`; never set `win.verifyUpdateCodeSignature`, which drops it; `tidy-release` warns and `release:check` fails without it — it is only electron-updater's second lock, the pinned verifier runs regardless, so never describe a missing one as "signatures not checked"); the app only reads that (no `setFeedURL`, no token, the renderer never sends URLs/paths/versions). Main: `electron/updater.cjs` (electron-updater wiring, IPC `updates:getState|check|download|install|setPrefs|openReleasePage` + push `updates:state` to the main window only, schedule 15 s after ready-to-show then `checkDue` every 10 min = 4 h / 30 min after offline, logger `userData/logs/updater.log`, prefs + install attempt in `userData/updater.json`) and pure `electron/updater-rules.cjs` (no npm requires; reducer, kinds, error mapping to fixed Vietnamese texts, notes → plain text, profile dir; tested by `src/lib/__tests__/updaterRules.test.ts`). - Signing & hardening (docs/SIGNING.md). Release .exe files are signed by electron-builder `build.win.signtoolOptions`: `certificateSha1` = the author's self-signed cert (`CN=Nguyễn Giang Minh (Jame Steven), C=VN`, `7489ABFAC1A7CD23D5FFB0785CA7CAB414AE49ED`, valid to 2036-10-03) in `Cert:\CurrentUser\My` (a key-less public copy also sits in `Cert:\CurrentUser\CA` since its creation — no trust, leave it, remove it together with the `My` entry when retiring the cert), one SHA-256 signature, RFC 3161 DigiCert timestamp, explicit `publisherName`; `forceCodeSigning: true`; `signExts` names Electron's 4 unsigned DLLs (ffmpeg, vk_swiftshader, vulkan-1, dxcompiler). A missing cert fails the build ("Cannot find certificate"). The build log may show "Nguy?n" (child PowerShell codepage): cosmetic, the packaged files carry correct UTF-8. Never add `certificateSubjectName`, `signtoolOptions.sign`, `certificateFile`/password, `toolsets.winCodeSign`, `win.verifyUpdateCodeSignature`, `asar: false`, `asarUnpack`, `disableAsarIntegrity`. Author pitfall: electron-builder's normalizePackageData turns `author` "Nguyễn Giang Minh (Jame Steven)" into name "Nguyễn Giang Minh" + url "Jame Steven", so `build.extraMetadata.author.name` re-sets it after normalization (CompanyName / uninstall Publisher); `extraMetadata` arrays are UNIONED (a test build adding a pin ships [REAL, TEST]); tested by `src/lib/__tests__/buildConfig.test.ts`. Trusted signers = top-level `package.json` `sanovids.signers` (thumbprints; NOT under `build`, which is stripped from the packaged package.json; inside app.asar, whose integrity hash lives in the exe — someone who can write the install folder can replace both, so this guards against accidental / partial edits, not malware running as the user). Rotation ("ghim trước, ký sau"): add the new thumbprint in a release still signed with the old cert, ship it, then switch signing (`certificateSha1` + `SIGNER_THUMBPRINT`) — `release:check` refuses the merged shortcut; do it well before 2036-10-03 (a timestamped signature stays accepted after expiry: NotTimeValid is ignored only next to a timestamp; an untimestamped one becomes `bad-chain`). `electron/signature.cjs` (never requires 'electron', so main, updater and scripts share it): `readSignerPins`, `checkFileSignature` / `checkFilesSignature` (powershell.exe of the real Windows folder, allowlisted child env without PSModulePath / COR_* / COMPlus_* / DOTNET_*, `-NoProfile -NonInteractive -InputFormat None -Command <SIGNATURE_SCRIPT>`, no `-EncodedCommand` / `-ExecutionPolicy Bypass`, path only via env, 60 s, never rejects). Pure rules in `electron/updater-rules.cjs` (still no require): `SIGNATURE_SCRIPT` (one line, no `"` / newline / backtick, ASCII-escaped JSON between `SVSIG` markers, reports ConstrainedLanguage as `policy`), `parseSignatureOutput`, `judgeSignature` decision table in order: no pins → unknown/no-pins; ConstrainedLanguage → policy; bad output → verify-failed; status 2 → unsigned; status 3 → tampered (checked BEFORE the thumbprint: a modified file still reports the pinned signer); not Authenticode → verify-failed; thumbprint ∉ pins → other-signer (a same-CN impostor lands here); ok only for status 0 with chain flags ⊆ [UntrustedRoot], or status 1 + 0x800B0109 + a one-certificate chain flagged UntrustedRoot (NotTimeValid also tolerated when timestamped); anything else → bad-chain. Never decide on StatusMessage / Subject (localized). Tested by `src/lib/__tests__/signature.test.ts`. docs/SIGNING.md §5 holds the table in Vietnamese: keep it in sync. Self-check: main checks `process.execPath` AND the 6 Electron DLLs next to it (`hardening-rules.SELF_CHECK_FILES`: 4 author-signed, d3dcompiler_47 / dxil must stay "Microsoft Corporation") once, 3 s after ready-to-show, memoized; a bad DLL → `tampered`; `.pak` / locales / extra planted DLLs are NOT checked (say so in user docs); IPC `app:signature` (fromApp only; payload `hardening-rules.appSignaturePayload`) → preload `bdpDesktop.app.signature()` (inserted before `canvasapp:`; `updates:` stays the LAST preload key) → About. Fuses (`build.electronFuses`): RunAsNode, NodeOptions, NodeCliInspect, GrantFileProtocolExtraPrivileges off; EmbeddedAsarIntegrityValidation + OnlyLoadAppFromAsar on (the asar header is checked at start, each file lazily on first read: a modified app.asar does not start, or exits when the corrupted part is first loaded → reinstall); CookieEncryption deliberately OFF (enabling migrates the cookie store one way: never turn it on and then off). ## Conventions
- UI text in Vietnamese; model names stay English (Seedance 2.5, MiniMax-H3).
- zustand v5: a selector must return a stable value. Select primitives / existing objects, or wrap derived arrays/objects in `useShallow` (`zustand/react/shallow`). Never `useStore(s => s.list.filter(...))` without `useShallow` — it loops forever.
- Styling: plain CSS files next to components, using tokens from `src/styles/base.css` (`--panel`, `--accent`, `--ref`, …) and shared classes (`.btn`, `.btn-primary`, `.icon-btn`, `.input`, `.select`, `.textarea`, `.badge`, `.chip`, `.kbd`, `.empty`, `.section-title`, `.status-dot.<status>`, `.progress`). Prefix component classes per area: `cv-` canvas, `sb-` sidebar, `in-` inspector, `rq-` runs/queue, `vw-` views, `dg-` dialogs, `tb-` top bar, `tu-` top-up, `dv-` development mode (components/dev). Never use a bare utility name (`progress`, `ok`…) as a modifier class: `.progress` is the global progress bar.
- Shared components: `components/common/Modal.tsx`, `Toasts.tsx`, `Media.tsx` (`MediaImg`, `AssetAvatar`, `AssetChip`).
- Development mode UI (`components/dev/`): `DevPanel.tsx` ("Bảng phát triển", dialog kind 'dev', `actions.openDevPanel(tab)`), `DevSheets.tsx` (simulated login / SePay sheets mounted at the App root above dialogs, `data-top-overlay`), `devModel.ts` (pure texts / fault catalog / log filter / "Kiểm tra nhân vật", tested). User-facing wording: "Phát triển" / "DEV" / "credit dev"; "demo" only for legacy mock takes ("Demo cũ").
- Dark (default) and light themes (`lib/theme` pref 'system' | 'light' | 'dark'; light tokens under `:root[data-theme='light']`, so every colour must be a token). Keep it fast with 100+ scenes: memoize node components, avoid subscribing big components to the whole project.
- Working tree is LF (`.gitattributes` `* text=auto eol=lf`); only `.bat` files are CRLF. `LICENSE.txt`, `build/license_vi.txt`, `scripts/releases-repo/LICENSE.txt` (byte-identical), the generated `build/license-third-party.txt` and the signing `.ps1` scripts are UTF-8 with BOM (the NSIS license page and Windows PowerShell 5.1 need it): keep the BOM. LICENSE.txt clause 6 names the licence files that really ship (`LICENSE.electron.txt`, `LICENSES.chromium.html`, `THIRD-PARTY-NOTICES.txt`).
- Author / copyright strings are exactly "Nguyễn Giang Minh (Jame Steven)" and "© 2026 Nguyễn Giang Minh (Jame Steven) · Đồng hành: Sano Group" (NFC). Sano Group is credited only as the partner ("Đồng hành"), never as the developer.
- Never add a `beforeunload` handler in desktop code: it silently cancels `quitAndInstall` (the update never installs). Release notes / update data are rendered as text only (no `innerHTML` / `dangerouslySetInnerHTML`).
